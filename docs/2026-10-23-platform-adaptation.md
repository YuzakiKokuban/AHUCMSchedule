# LSPosed 可见性修复与鸿蒙适配试验

用户要求：只有 LSPosed 模块已激活时才显示小爱自动管理整块功能区，然后尝试鸿蒙适配。

## Android

- 当前根因：`moduleSupported = true` 只识别平台，不识别框架是否激活模块。
- 接入官方 libxposed service 102，Application 仅注册框架服务监听，不访问解锁前不可用的账号存储。
- 默认隐藏，收到支持 API 102 的框架服务才显示；服务死亡或查询失败后隐藏。状态只在内存中保存。
- Compose 订阅激活状态，功能区的开启、停止、说明一同显示/隐藏。自动管理偏好与激活状态独立。
- 无框架的平台默认隐藏。隐藏入口的同时阻止未激活时新建同步任务。

## HarmonyOS NEXT 原型

这是用户授权的适配试验，尚不是正式平台支持。技术路线由实现者选择：ArkTS/ArkUI 原生课表页面，ArkWeb 完成学校网页登录和同源只读同步，隔离的本地 ArkWeb 解析官方 XLS。相比全量 Kotlin/Compose 鸿蒙移植，这条路径可以先验证学校认证和 XLS 两个主要障碍；纯网页壳不能验证原生 UI，完整重写 BIFF8 解析器成本过高。

- 原生端：七天十四节网格、周切换、课程详情、通知和每账号离线快照。
- 认证：学校网页输入密码；仅用限定主页面源的消息端口捕获提交的学号，不读取密码，不把会话交给外部服务。
- 数据：复用现有 `ScheduleSnapshot` 字段和校验规则；XLS 使用随包提供的 SheetJS CE 0.20.3，保留许可和校验值。
- 网络：只允许学校 HTTPS 认证/教务源；读取完整官方 XLS、作息和只读通知接口。拉取失败或校验失败保留原缓存，通知不修改课表。
- 存储：账号以 SHA-256 标识。完整快照校验后保存至每账号独立文件，再原子切换活动账号指针。
- 浏览会话仅驻留隐私 WebView，退出进程后需重新登录。原型不保存密码和原始 Cookie。
- 鸿蒙中没有 Xposed UI 或驱动。

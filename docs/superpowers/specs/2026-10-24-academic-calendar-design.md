# 官方教学校历

后续交互已由用户明确修订：采用独立「校历」页面、统一顶栏同步、连接教务中的全局学期选择，以及与课表一致的月份导航；实际最终设计见 [自适应布局与共同学期设计](2026-10-24-adaptive-layout-design.md)。下文保留初版设计背景。

用户在查看学校现有功能后选择先实现校历；前五项保持原待办。本轮在 Android/Windows 共享界面提供校历入口、学期切换、按月查看、教学周及学校日期备注。保留 miuix 主题，以左侧教学周、七列日期、今天高亮和备注标记形成清晰的校历。

使用现有已登录 SchoolClient，仅调用学校校历页和 `/new/xlxx/data` 只读接口。校历页的学期选项为可选来源；月份、日期、周次及备注解析自官方响应。不推算放假、调休或修改个人课表。校历独立缓存，按账号隔离，多学期保存，成功校验并原子落盘才替换；失败、未发布学期和会话过期保留旧数据并提示。未同步学期可选择并尝试获取，空响应明确提示未发布，不能覆盖旧缓存。

采用独立 core 模型/解析器/存储及共享 Compose 页面，在课表页内提供“课表 / 校历”入口，不扩大底部导航。校历刷新按需执行，不绑在每五分钟课表同步上；没有登录也能查看已缓存学期。选学期先显示该学期缓存，再可同步；不会把上一学期的日期显示在新学期标题下。账号变更、页面离开和取消时丢弃过期异步结果。

备选方案是嵌入学校网页（离线不可用且移动布局不佳），或从个人 XLS 推算校历（不能提供官方备注）；因此选择原生解析与独立缓存。

匿名测试覆盖跨月跨年、官方周次、备注、无数据、登录页/非法响应、日期/周次/列位置异常、重复和缺失日期、缓存写失败保留原数据、多账号隔离、学期切换及离线展示。最终运行 core/Compose 测试及 Android 编译；只读实网验证不保存账号密码或个人课表。

实现约束：官方日历按完整教学周生成，要求首日周一、末日周日。已有同学期缓存时，缩短日期范围的响应会被拒绝，避免残缺数据覆盖已知完整范围。接口没有总天数或起止日期元数据，首次同步时无法识别整周或整月恰好从末尾消失的响应；同时，学校若真的缩短学期范围，也会保留旧缓存并提示核对。

# Windows、安卓横屏和平板布局重设计

## 意图与范围

用户要求 Windows 采用桌面布局，同时安卓手机横屏和平板可用。本轮保持现有 miuix、动态配色、品牌和数据行为；重做布局与交互组织，不增加新的教务业务功能。此前校历改动保留，五项功能待办独立。

当前所有平台共用手机 Scaffold、底部导航、固定 64dp 节高、课程弹窗和纵向单月校历。Windows 初始窗口 1180×820dp，安卓未锁方向；“可以旋转”并不代表当前横屏布局可用。

## 方案

推荐：共享状态与内容组件，按平台及实际窗口约束选择布局外壳。Windows 采用桌面工作区；安卓按可用宽高采用手机、紧凑横屏、平板布局。

备选统一双栏只按宽度切换，实现较少，但手机横屏可能被误当作平板；为每个平台复制整套页面会使同步行为和修复重复维护。因此保留共享内容，明确区分输入设备、窗口宽度和高度。

## Windows

- 左侧固定导航，提供“我的课表、校历、调课通知、连接教务”；同步状态在侧栏底部，主要同步操作在内容工具栏。
- 课表工具栏单行放学期、日期范围、教学周与周切换。中央为周课表；宽度足够时右侧约 280–320dp 显示选中课程详情，未选择时提示选择课程，避免虚构待办和统计。
- 默认窗口宽度 >=1000dp 使用约 192dp 侧栏，否则使用约 72dp 导航轨道；扣除导航后宽度 >=900dp 且高度 >=480dp 时显示约 288dp 详情区，否则使用可关闭的详情浮层。不会强制拉大窗口或通过缩小字体塞下内容。
- 点击选课和键盘激活课程保持一致；支持可见焦点、Tab 顺序、Esc 关闭详情。周切换快捷键仅在课表页面生效，输入框编辑时不截获方向键。
- 校历宽屏展示并排月份与日期详情；通知采用列表＋原文详情；连接页限制表单宽度，与同步和导入说明分区，不把输入框拉满窗口。

## 安卓手机横屏

- 按实际可用高度判断紧凑横屏，不只判断屏幕方向。默认条件为可用高度 <480dp 且宽度 >=600dp，精确数值可由截图验证微调。
- 左侧约 72dp 导航轨道，取消底部导航；合并页标题、学期周次与同步/周切换，减少顶部占高。
- 周课表保持七天和十四节，节高约 48–56dp，字号和触摸目标保持可读；允许纵向滚动，不要求一屏显示全天。日期表头与节次对齐，不能用缩放整张界面适配。
- 课程详情以可滚动弹层展示，不强塞第三栏。校历优先显示单月，日期详情使用弹层。系统栏、手势区、挖孔与键盘占用按安全区域处理。

## 平板与安卓分屏

- 宽度 >=600dp 使用约 72dp 导航轨道；扣除导航后宽度 >=900dp 且高度 >=480dp 时采用主内容＋约 288dp 详情双栏，保留触控尺寸，其他尺寸使用单个主内容区。
- 平板较宽时课程详情、日期备注和通知原文与列表并排；窄分屏时自动退回单栏，关闭详情不会丢失当前周/月份/学期。
- 窄窗口 <600dp 保留底部导航和单栏。各布局统一为“课表、校历、通知、教务”四个正式目的地，不在窗口缩放时改变用户所在目的地。

## 布局与状态边界

- 导航目的地、当前周、校历学期/月、课程/日期/通知选择由页面之上的状态持有。调整窗口和旋转不应重置它们或启动第二个同步循环。
- 校历控制器生命周期与目的地绑定，不与“单栏还是双栏”的条件分支绑定；重排不重新创建控制器、取消正在进行的正常刷新或丢失反馈。
- 本轮拆出布局外壳、课表头/网格/详情、通知列表/详情、连接表单和校历月份/详情，避免继续扩展 App.kt 中的一份大布局。
- Windows 外壳通过明确平台能力选择，测试使用可注入的平台与窗口尺寸；不通过操作系统名称字符串或设备型号猜测平板。
- 课表密度按可用宽高设定有界行高与字号，显示长课程名时允许省略，但完整名称始终可通过详情及无障碍语义读取。并行课程仍完整保留。

## 验收

验证 Windows 1180×820、1440×900、缩窄 760×650，安卓手机 390×844、844×390，平板 800×1280、1280×800，以及安卓分屏 600×700（均为逻辑 dp）。

检查导航和主要操作可触达、长标题和并行课程无重叠、课表表头/时间轴对齐、日期备注/课程详情/通知原文可读、无课与未登录状态清楚。窗口缩放和旋转过程中保留选中状态、同步任务不重复、密码输入不因旋转重新提交。覆盖深色模式与字体放大 1.3 倍；更大字号时允许退回单栏。

先写布局策略和状态保留测试，再实现；新增上述尺寸截图及语义交互验证，运行 core、Compose 桌面测试和 Android 编译。模拟尺寸不等同于真机旋转与触摸验收，需分别记录。

## 布局方向

推荐整体方向为“Windows 桌面工作区＋安卓按宽高自适应”。建议所有布局均采用四个正式目的地，校历从课表页的子切换提升为导航项，避免桌面与手机结构不一致。交互布局稿使用匿名演示课程，不代表真实课表。

## 用户确认的交互修订

用户随后明确要求并指示继续实施：名称仅为“校历”；校历是独立页面；删除校历专用同步按钮，顶栏一次同步同时刷新所选学期课表和校历；翻月使用与课表一致的左右箭头和“本月”按钮；学期选择放在“连接教务”，同时控制两页。

实施决定：选项使用学校提供的学期与已有缓存的并集，缺少任一数据时明确显示该学期空状态；选定后先显示缓存，已登录则获取两种数据。显式选择按账号保存。历史学期同步不自动替换当前学期的系统日历/小爱数据；Windows 手动 ICS 导出操作正在展示的课表，Android 的系统日历和小爱入口明确限制为已确认的学校当前学期。当前学期自动集成仅在确认返回的是学校当前学期时运行。没有选择时默认学校当前学期。

旋转/窗口重排保留导航、选周、选月与详情选择；共用同步门闩避免同账号在途刷新重复发起。校历本身不再持有独立网络控制器，其刷新由共同同步流程管理。

平板竖屏较高且不足以并排月份时，连续上下展示两个月，避免仅放大单月后留下大块空白。字体放大时导航轨道同步增宽；大字号导致详情宽度不足则回退单栏。

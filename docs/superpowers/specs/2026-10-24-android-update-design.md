# Android 检查更新、关于与 0.4.1 发布

## 目标
Android 增加「关于」入口、版权与许可展示，以及应用内下载官方 APK 并交给系统安装器的更新流程；发布 0.4.1，versionCode 递增为 7。

## 方案选择
用户选择应用内下载 APK；另一个方案是打开 GitHub Release 页面，开发成本较低，但不满足本次选择。沿用 Compose / miuix，在「连接教务」页增加 Android 专属「关于」按钮。

## 界面与行为
- 关于页显示应用名、实际安装版本、© 2026 YuzakiKokuban、Apache-2.0、项目主页及随包第三方许可声明。
- 手动检查 GitHub 项目最新公开正式 Release，排除草稿和预发行版；显示当前已最新、检查失败或可用版本与发布说明。不自动下载。
- 用户点击下载后，在应用私有缓存内下载 APK，显示进度，防止重复任务；失败可重试。检查与下载不携带学校账号、Cookie 或课表。
- 下载校验包括官方项目资源地址、大小、SHA-256、APK 包名、版本号和签名证书与当前安装一致。失败禁止安装。
- 下载完成后点击安装；未允许安装未知应用时，引导至本应用的系统授权页，返回后仍需确认安装。通过 FileProvider 临时只读授权交给系统安装器，用户完成最终确认。
- 同版本不更新，不接受降级；检查与下载超时提供明确提示。使用现有正式发布签名以兼容覆盖升级。

## 实现者决定
更新状态由 Android ViewModel 管理，旋转屏幕保留任务；进程终止后重新检查和下载。使用已有网络与 JSON 能力，避免新增下载框架。版权主体采用仓库作者 YuzakiKokuban。

## 验证与发布
先测试版本比较、Release 解析、地址与摘要校验、失败状态，再验证关于入口、下载/安装授权流程并构建签名 APK。运行现有核心、Android、桌面及小爱测试。更新发布说明，提交并推送 v0.4.1，等待 CI 双端构建和签名验证完成，再发布正式 Release，核对附件与校验值。

## 范围
本轮仅在 Android 暴露更新与关于界面，不增加后台自动下载、强制更新或鸿蒙更新支持。Windows 沿用统一版本发布流程。

## 用户追加要求
- 所有产品 APK 统一使用既有官方证书；debug/release 配置均禁止其他证书，未配置私钥时仅生成未签名包。PR 不传递签名秘密，受信 main/标签构建使用官方签名。
- 返回改为左上角 miuix ChevronBackward 图标，许可证页面支持系统返回。
- 审查并合并依赖 PR #6、#7、#8、#9；Kotlin 编译插件版本必须一致，最后重新验证集成版本。
